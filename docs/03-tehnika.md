# Технический план сборки `.sb3` (как получается «вау» и как оно не ломается)

## 1. Почему это будет настоящий проект, а не «нарисованные картинки»
`.sb3` — это ZIP: `project.json` + ассеты с именами `<md5>.<ext>`. Собираем его **программно** (Python-генератор), а не руками в редакторе:

```
art/  ──►  tools/pipeline_art.py   (хромакей, обрезка, палитра, ресайз)
audio/──►  tools/pipeline_audio.py (синтез музыки/фоли, TTS-озвучка, mp3)
            │
            ▼
        tools/build_sb3.py         (project.json + ассеты → dist/Фамилия_Имя.sb3)
            │
            ▼
        Валидация: scratch-parser (структура) + headless scratch-vm (прогон логики)
```

Плюсы: точные координаты, прозрачность, повторяемость, отсутствие ручных ошибок в 1000+ блоков, быстрый перебаланс.

## 2. Спецификация ассетов

| Ассет | Размер | Требование |
|---|---|---|
| Сцена | 480×360 (координаты −240…240 / −180…180) | 4:3 |
| Фон | 960×720 (2× = резко на Retina), JPEG q88 или PNG | **без текста**, без «мельтешения» в центре |
| Спрайт | до 480 px по длинной стороне, PNG **RGBA** | **истинная прозрачность, без белого/зелёного ореола** |
| Хромакей | генерация на `#00FF00` → удаление по HSV с допуском + feather 1–2 px + деспилл краёв | снеговик/белая коза не страдают: удаляем только насыщенный зелёный |
| Палитра | LUT: тени `#0B1B33`, полутон `#1E3A5F`, снег `#F2F5F7`, свет `#FFC96B`, акцент `#C0392B`, аврора `#7A5CC4` | «единая цветовая гамма» = 3 балла |
| Звук | mp3 96–128 kbps моно/стерео | суммарно ≤ 15 МБ, проект ≤ 50 МБ (лимит scratch.mit.edu) |

### 2.1. Текст и частицы (новое в 1.5)

| Назначение | Файлы | Полотно | Как используется |
|---|---|---|---|
| Подсказки актов | `art/ui/hint1..3.png` | 960×84 (res=2 → 480×42 единицы) | костюмы `акт1..3` спрайта **«Плашка»** |
| Субтитры реплик | `art/ui/cap1..10.png` | 960×84 | костюмы `реплика1..10` того же спрайта |
| Снежинка | `art/ui/snowflake.png` | 96×96 | частицы снега, 5–12%, призрак 25–70% |
| Искра салюта | `art/ui/spark.png` | 96×96 | клоны фейерверка, 9–16% |
| Подписи финалов | `s2027_sub.png`, `lose_sub.png` | 571×82 / 919×94 | спрайт **«Подпись»** |

**Почему один спрайт на весь текст.** Облачка `say` в Scratch рисуются поверх
спрайта-говорящего и не подчиняются сцене: они закрывали титр, персонажей и
подсказки. Теперь текст — статичная картинка в нижней полосе (y = −157),
а подсказки актов и реплики используют **один и тот же спрайт в одной точке**,
поэтому наехать друг на друга физически не могут. Правила и аудит —
`docs/09-kompoziciya.md`.

## 3. Архитектура проекта (вариант A, применимо к любому)

### 3.1 Спрайт «Режиссёр» — единственный источник истины
Все переходы сцен идут через один спрайт, а не через 50 рассылок сообщений по всему проекту. Это ключ к критерию «работает без ошибок при повторном запуске».

```
по щелчку зелёного флага:
  Сброс игры                     // см. 3.2
  Пролог                         // сцена 0, диалоги, «передать и ждать»
  Акт 1 — Ночной город
  если жизнь > 0 → Акт 2 — Зимний лес
  если жизнь > 0 → Акт 3 — Крыша
  если победа = 1 → Финал-победа иначе Финал-проигрыш
```

### 3.2 Блок «Сброс игры» (защита от 90 % ошибок повторного запуска)
```
Сброс игры:
  остановить другие скрипты          // гасим всё, что осталось от прошлой игры
  удалить все клоны                  // снег/искры/звёзды — иначе утечка и лаги
  игра = 0 ; сцена = 0
  жизнь = 3 ; звёзды = 0 ; подарки = 0 ; таймер = 60 ; победа = 0
  скрыть всё лишнее, перейти в фон «Мастерская»
  установить эффекты (яркость/призрак/размер) по умолчанию
  стоп все звуки
```
Правила, которые соблюдаем:
- клоны создаём **только** из явного `создать клон` в цикле с ограничением `повторять 40`, и всегда `удалить этот клон` при выходе из сцены;
- ни один спрайт не «живёт» между актами: каждый акт сам поднимает своих;
- таймеры — на переменных (`таймер_игры`), а не на встроенном сенсоре `таймер`, чтобы сброс был честным;
- никаких `всегда` без условия выхода (`если игра = 1`), иначе скрипты будут бороться друг с другом после рестарта;
- `передать и ждать` вместо гонки сообщений там, где важен порядок (пролог → акт).

### 3.3 Параллакс (главный «вау-эффект» на 2D)
4 слоя-клона на акт, общая переменная `скролл`:
| Слой | Скорость | Что это |
|---|---|---|
| 0 | 0.05 | небо, луна, звёзды |
| 1 | 0.20 | дальние крыши / лес |
| 2 | 0.45 | дома, ёлки |
| 3 | 1.00 | земля, сугробы, платформы |

Клоны двигаются в `всегда`, при выходе за край — «заворачиваются» на другую сторону. Камера «едет» сама: `изменить скролл на скорость_бега`. Дополнительно — **тряска камеры** (смещение всех слоёв на 2–3 px при ударе) и **плавное появление** (призрак 100→0).

### 3.4 Физика героя (платформер без тормозов)
```
всегда:
  изменить vy на -1.2                  // гравитация
  изменить y на vy
  если касается [платформы] и vy < 0:  // приземление
     установить vy 0 ; на_земле = 1
  если нажат [пробел] и на_земле = 1:
     установить vy 13 ; звук «прыжок» ; на_земле = 0
```
Коллизии — по **невидимым спрайтам-платформам** (надёжнее, чем `касается цвета [белый]`: белый снег на белом фоне = ложные срабатывания). Платформы — один спрайт с несколькими костюмами-сегментами + клоны.

### 3.4.1. Как сделано в 1.6 (реальные числа из `tools/sb3/game.py`)

```
пол GROUND = -80;  прыжок vy = 15;  гравитация 1.3   -> апекс ~86 пунктов
цикл физики: 1 шаг за кадр (в конце цикла «ждать 0»)

Звезда (клон):  setv клон 1; показать; размер 11..14
                если акт = 1 -> перейти x 270, y (случайно -100..-20)
                иначе        -> перейти x 270, y (случайно -58..62)
                повторять пока (x < -270 или акт = 0):
                    изменить x на -скорость; повернуть на 4
                    если касается [Мила]: звёзды +1; звук «подбор»; удалить клон
                    ждать 0
                удалить клон

Сугроб (клон):  удар, ТОЛЬКО пока Мила стоит на земле: |x - x(Мила)| < 20 И y(Мила) < -78
Ёлка   (клон):  удар, только если |x - x(Мила)| < 24 И |y - y(Мила)| < 34
Снежок (клон):  летит 6.5 шагов к Миле, удар по касанию

скорость: акт 1 = 4.2, акт 2 = 6.5, акт 3 = 6   (паузы: сугроб 3.2-4.4 с,
ёлка 2.6-3.4 с, снежок 1.3-2.0 с)
```

Почему удар считается по расстоянию, а не по `касается [Мила]`: спрайты
нарисованы на полотне 420×199 (сугроб) и 267×420 (ёлка), и Scratch проверяет
касание по габаритной рамке. Рамка сугроба шире прыжка: окно контакта — около
32 кадров, а прыжок длится 23 кадра. Физически невозможно перепрыгнуть.
Расстояние по `x` (и по `y` для ёлки) даёт честное окно: сугроб задевает, только
пока Мила низко, ёлка — только если совпала и по высоте.

Почему `ждать 0` в каждом цикле движения: без него Scratch крутит цикл, пока
хватает бюджета кадра (25 мс). На быстрой машине сугроб пролетал всю сцену
за 1–2 кадра, на медленной — за 90. С `ждать 0` шаг всегда равен кадру, и игра
одинаково проходима на любом компьютере.

Почему скрипт клона звезды **один**: `when_clone` внутри цикла `for n in (1, 2)`
создавал два одинаковых обработчика. Клон получал оба: вариант «для акта 2»
в первом акте видел `акт ≠ 2`, сразу выходил из цикла и выполнял `удалить клон` —
звезда исчезала в кадре рождения, и счётчик не рос. Высота теперь выбирается
внутри одного скрипта по номеру акта.

### 3.5 Частицы
- **Снег**: 25 клонов, 3 костюма (крупная/мелкая/«пух»), у каждого свои скорость, призрак 20–70, угол падения зависит от переменной `ветер` (в лесу ветер растёт → снег летит боком).
- **Искры от саней**: 6 клонов по 0.3 с.
- **Пар из трубы / дыхание**: 4 клона, размер растёт, призрак растёт.
- **Виньетка и луч света**: 2 статичных спрайта поверх всех слоёв (создают «киношную» глубину).

### 3.6 UI и «экран 15 баллов»
Часы «23:5X» (стрелки/цифры меняются от таймера), 3 сердца-жизни, счётчик звёзд, всплывающие диалоги с портретом говорящего, кнопка «Ещё раз», финальный титр «2027» с козочкой, кнопка «Звук вкл/выкл» (забота о жюри, которое смотрит без звука).

## 4. Почему не ломается на 2-м запуске — отдельный протокол тестов
1. `scratch-parser` — структурная валидация ZIP/JSON/ассетов на каждом билде.
2. Headless `scratch-vm` (`tools/run_vm.js`) — фактический прогон `.sb3`:
   флаг → титр → пролог → три акта → победа; отдельно проигрыш и кнопка «ЕЩЁ РАЗ»;
   проверяется, что переменные вернулись к стартовым, клонов не больше нормы,
   в рантайме нет ошибок. Протокол прогонов — `docs/08-proverka-zapuska.md`.
3. Ручной чек-лист в браузере (см. `docs/05-plan-i-sdacha.md`): 5 полных проходов (победа, проигрыш, рестарт после победы, рестарт после проигрыша, рестарт во время диалога).
4. Запас прочности: игра не должна содержать `ждать до` на сенсоре, «вечных» звуков без `стоп`, и клонов без удаления.

### 3.1. Три ловушки формата `.sb3`, на которых уже обжигались

| Ловушка | Как проявляется | Как проверяем |
|---|---|---|
| Примитив рассылки должен быть `[11, ИМЯ, id]` (имя первым!) | виртуалка ищет рассылку по имени-как-id, не находит и **молча** не запускает обработчики: после флага не идут ни пролог, ни акты | `tools/lint_sb3.py` сверяет имя и id; `tools/test_build.py` падает при перепутанном порядке |
| Рассылка запускает обработчики **и в клонах** | скрипт-спавнер клонирует сам себя у каждого клона — число клонов растёт лавиной, игра тормозит | у спавнеров есть локальная переменная `клон`; в прогоне видно число целей по именам |
| У костюма обязательны `width`, `height`, `rotationCenterX/Y` | Scratch ставит точку вращения (0,0): спрайт «съезжает» и вращается вокруг угла | размеры пишутся из самих PNG/JPEG, линтер требует все четыре поля |
